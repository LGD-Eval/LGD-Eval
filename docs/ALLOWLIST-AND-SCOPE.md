# ALLOWLIST-AND-SCOPE · 豁免与扫描范围的声明格式

> 两个文件，都在被测对象的根目录下、`.lgd/` 子目录里。**没有它们就是"全扫描、零豁免"**，这是默认也是推荐状态。
> 设计原则：**注释不能关掉检查；只有可审计的声明能。** 声明本身也不构成安全性证据，只会被记进报告。

## 一、`.lgd/allowlist.json`（规则级豁免）

```json
{
  "entries": [
    {
      "rule": "R-SEC-07",
      "file": "scripts/main.py",
      "text_sha256": "<该行 strip() 之后的 sha256>",
      "reason": "构建产物目录清理，不涉及用户数据",
      "reviewer": "steven.zhao"
    }
  ]
}
```

判定三要素全部满足才算豁免：

1. `rule` 命中同一条规则号；
2. `file` 是相对路径且与命中文件完全一致；
3. `text_sha256` 等于**命中那一行**（`strip()` 后）的 sha256 —— 改一个字豁免即失效。

**硬限制**

- `R-SEC-09 / R-SEC-10 / R-SEC-21`（凭证外泄、环境变量批量外发）**永不可豁免**，写了也不生效；
- `reason` 为空视为无效；
- 有任一豁免生效时，该对象**最高只能到 A（89），不可能 A+**；
- 生效的豁免会以 `ℹ️ 备案豁免 N 条` 的形式打印在报告里，**不隐藏**。

**未备案的豁免注释**：代码里写 `# skillgate: ignore` 或 `# lgd: ignore` 但 allowlist 里没有对应条目，
会被当作"试图关闭检查"计 8 分并触发高危封顶（实测 86/A → 62/C）。

## 二、`.lgd/scope.json`（扫描范围声明）

```json
{
  "fixture_dirs": ["tests/fixtures", "benchmark/corpus"]
}
```

- 只有列在这里的目录会被跳过；
- 跳过行为会打印 `⚠️ 声明跳过目录：…（声明本身不构成安全性证据）` 并写入报告；
- 文件无法解析时，按**全部扫描**处理（fail-closed，不 fail-open）。

## 三、为什么取消原来的目录名单

旧实现固定跳过 `samples/`、`demo/`、`benchmarks/`、`corpus/`、`fixtures/`。
实测：把凭证外发载荷放进 `demo/payload.py`，得分 **100/A+、安全 25/25、零命中**。
"评测器自带的攻击样本目录"这个理由，对攻击者来说正好是一个免费的隐身衣。

## 四、最小可用做法（给被测方）

1. 不要建 `.lgd/` 目录 —— 默认全扫描，最容易通过；
2. 确有回归夹具需要排除时，才写 `scope.json`，并在 PR 里说明为什么必须排除；
3. 需要豁免时，写 allowlist 并**接受封顶 A**。
