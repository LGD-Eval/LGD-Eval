# 2026-11-21 三方同批对照：同一 7 个攻击样本，三个引擎各怎么说

结论先说：**这不是一场「我们更强」的对照，是一次自检。** 三个引擎在同一批样本上给出
互不相同的答案，我们因此发现了自己产品线里的一个发布断层，并在本轮修掉。

## 1. 样本与判读口径

7 个样本（`P1`–`P7`）全部是**构造出来的攻击包**，不是真实第三方技能：凭证读取后外发、
载荷藏在 `demo/`、行内 `ignore` 注释、仅文档 + 隐形字符注入、`SKILL.md` 内 base64 注入、
未备案 allowlist 伪造指纹、`scope.json` 把 `demo` 声明成夹具。

判读口径只有一条：**该样本是否被判为否决（不给过）**。分数高低不作优劣依据——
三家评分刻度不同，横向比分数没有意义。

## 2. 三家结果

| 样本 | LGD-Eval 源码（修复前） | LGD-Eval 源码（修复后） | LGD-Eval 制品 `1.0.0` | NVIDIA SkillSpector v2.12.0 (`--no-llm`) |
|---|---|---|---|---|
| P1 凭证外发 | 否决 49/D | 否决 49/D | 70 分，不否决 | DO_NOT_INSTALL（58，TT3） |
| P2 载荷藏 demo/ | 否决 49/D | 否决 49/D | 65 分，不否决 | DO_NOT_INSTALL（58，TT3） |
| P3 行内 ignore 注释 | 62 分，不否决 | 62 分，不否决 | 70 分，不否决 | SAFE（0） |
| P4 仅文档 + 隐形注入 | 否决 49/D（INCONCLUSIVE，rc=2） | 否决 49/D | 65 分，不否决 | CAUTION（30，P2/AE4） |
| P5 SKILL.md 内 base64 注入 | 59 分，不否决（rc=2） | **否决 49/D（R-SEC-24，rc=2）** | 65 分，不否决 | SAFE（0） |
| P6 未备案 allowlist | 62 分，不否决 | 62 分，不否决 | 70 分，不否决 | SAFE（0） |
| P7 scope.json 声明夹具 | 否决 49/D（INCONCLUSIVE，rc=2） | 否决 49/D | 65 分，不否决 | CAUTION（30，P2/AE4） |
| **拒判数** | **4/7** | **5/7** | **0/7** | 2 项 DO_NOT_INSTALL + 2 项 CAUTION |

SkillSpector 的 `recommendation` 取值只有 `SAFE / CAUTION / DO_NOT_INSTALL`，
`rc` 为 0/1，属「分数 + 建议」型；本引擎是「分数 + 否决/无法判定」，两者不是同一种产物。

## 3. 这张表暴露的三件事

1. **发布断层（本轮 P0）**：源码拒判 4/7，`1.0.0` tgz 拒判 0/7。外人下载到的制品
   与源码不是同一套规则。修法是把 `main` 的硬化源码重新打包成 `1.0.1`，并在 README
   把下载链接指到新版本——本轮已做，`docs/RELEASE-NOTES-1.0.1.md` 记录。
2. **base64 是最便宜的绕过（本轮 P1）**：编码后的注入话术只扣 6 分、不映射规则号，
   等于告诉攻击者「把话 base64 一下就行」。本轮把它升为 CRITICAL（`R-SEC-24`），
   命中即封顶 49/D 并 `exit 2`。SkillSpector 在 P5 上给 SAFE，这条它没有。
3. **不是所有不否决都是漏检**：P3（行内注释）与 P6（未备案 allowlist）在本引擎里
   「不否决」是设计结果——它们扣分但不到否决线；我们不在这些样本上宣称「检出」，
   只如实写分数与理由。

## 4. 怎么复跑

- 源码侧：`python skills/lgd-eval/scripts/skillgate.py scan <样本目录>`
  （`scan` 的输出含 `LGD Trust Score`、`⛔ 安全否决` 行与 `result=` 结论行）
- 制品侧（同一口径）：`node bin/lgd-eval.js <样本目录>`（解包 `lgd-eval-1.0.1.tgz` 后；
  这个 CLI 走 `evaluate.py` 口径，没有 `scan` 子命令）；门禁口径用
  `python vendor/scripts/skillgate.py scan <样本目录>`（`scan` 输出同构，含否决行）
- 外部工具：`pip install git+https://github.com/NVIDIA/skillspector`，
  再 `skillspector scan <样本目录> --no-llm --format json`（JSON 走 stdout）
- 本仓 `tests/test_safety_veto_hardening.py` 把 P1/P2/P4/P5/P7 的形态钉成了断言，
  任何一侧再退化，`pytest` 先红

## 5. 边界

- 7 个样本是我们自己构造的，不代表真实世界的攻击分布。
- SkillSpector 本轮以 `--no-llm` 运行（无 LLM 凭据），纯静态，能力上限本就低于其全量模式。
- 本页只想说明一句可核查的话：**同一批样本上，我们的源码与制品现在给出同一答案。**
